## Why

`ProbeRequest` carries one profile and one `resume`/`pause` (`worker_request.ProbeRequest` fields), so a pod cannot run a sharing pair; the progress receipt (`runner.write_progress_receipt`, the ONE definition after L4a, schema `h-probe-training-progress-v1`) has no block, pair, cell or authority fields and cannot tell inherited warm-up steps from the cell's own; every worker output lives in a flat two-part namespace (`worker_snapshot._path`: `run|capture|verification|worker` plus a name), so two cells' artifacts collide; and every journal read replays the whole corpus (`capture.read_prepared_corpus` runs `prepare_documents` including pysbd; called from `seals.py` in the walk, from `journal.py` twice), which is blocking at the 100 MB corpus (R1 in the plan). `SealMemo` (`seals.py`) already memoizes seal admission by digest for one process and one root; the corpus memo is the same shape one level down.

## Design (brief-ready)

- D1 `h-probe-worker-request-v3`: `cells: (donor, recipient)` as two `HProfile`s in donor-first order (pair rule from `codec_handoff.require_pair`), per-cell `resume` and `pause`, a block binding `{block_id, pair_id, source_digest, seed}`, the sealed `RunAuthority` (required for scientific classes, refused for smoke), inputs under `run/<cell>/`. v1 and v2 read as the same class (one profile, no cells); `parse_probe_request`'s exact-key recovery stays the one reader, reached from `worker_command`, `worker_transport`, `h_probe_launch` (two sites). The frozen request fixture and `tests/test_h_worker_request_authority.py` digests are re-frozen once, with the old digests retracted in the test docstring (house rule 4).
- D3 `h-probe-training-progress-v2`: adds `block`, `pair`, `cell`, `authority_digest`, `handoff` (the `h-codec-handoff-v1` record reference, null for a donor or a smoke run), and splits `inherited_warmup_steps` from `own_optimizer_steps`; `successful_optimizer_steps` keeps its meaning as the cell's own count. `runner.write_progress_receipt` is the only writer, so L4a's hand-off receipt (status `checkpoint`, phase `codec_warmup`, step `warmup_steps`) becomes a v2 receipt through the same call (`codec_handoff.py` therefore joins the member touch set for that call's keywords; nothing else in it moves). `read_training_progress` reads v2; `trace_capture._SCHEMAS` keeps the v1 name so an old receipt is recognized and refused by name. The non-member readers `h_probe_collection.py` (the `stopped` branch) and `h_probe_resume.py` (the paused-receipt check) land in the SAME DG-A commit.
- Cell namespace (Q9): `run/<cell>/...` for every per-cell artifact, `worker_snapshot._path` admits three-part paths whose first two parts are `run` and a cell name; `worker_request`'s input-namespace and resume checks ("worker input is outside the declared input namespace", "worker resume must bind its training receipt in run/") move to the cell form. One slice owns the whole namespace change.
- D11: one MLflow run per cell, named `h-worker-{cell profile identity}` (keeps `h_wave_monitor`'s run-name search working), one metrics file and one worker log per cell, tags `block`, `pair`, `cell`, `run_authority`; `tiny` stays derived from the authority.
- D14 corpus memo: `read_prepared_corpus` gains a process-scoped memo keyed by the prepared-corpus digest (the `SealMemo` ownership rule: one process, one root; a fresh process has none), threaded from the runner's walk and the journal readers; the replay count is MEASURED on the tracer fixture before and after and quoted in the handoff.
- The pair loop in the worker (`worker_execution.execute_probe_request`): cell 1 trains to completion; `materialize_codec_handoff` (L4a) hands off; cell 2 trains; DH-15: a donor scientific gap after warm-up lets the recipient run from the sealed warm-up, a donor execution defect stops the pair, the recorded reason is the prelude's `H1ExclusionReason` (NONFINITE_ENDPOINT vs READER_REFUSAL), never a free string. The result record keeps `h-probe-worker-result-v1` for L4c to version (D2 is L4c's).
