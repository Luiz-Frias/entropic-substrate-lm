## Why (measured at `a43ef9f`)

- E runs are created with `params={exp, seed, config_hash, git_sha}` and `tags={exp, config_hash}` (`ladder/capture/reader/sinks.py:build_sink`, `:237-268`; constants `CONFIG_HASH_TAG = "config_hash"`, `EXP_TAG = "exp"` at `:153-154`). `config_hash` is `sha256(config without train.seed)[:12]` (`sinks.py:206-219`); `mlflow_aggregate._leaf_runs` keeps only runs whose `config_hash` tag is set and not a parent (`mlflow_aggregate.py:66-74`, regex `^[0-9a-f]{12}$` at `:63`). `git_sha()` (`sinks.py:174`) shells out to git.
- H pod runs are created with `params={"run_class"}` and `tags={"schema": "h-probe-worker-result-v1"}` (`worker_command.py:191-203`); the tracer with `params={run_class, precision}` and `tags={"schema": "h-tiny-trace-v1"}` (`composition/wiring/h_tiny_tracer.py:152-160`). Neither carries `exp`, `config_hash` or `git_sha`, so no H run is ever a leaf for aggregation (matrix A6). The worker knows `request.code_commit` and `request.image` (`worker_command.py:180-185`), so `git_sha` needs no subprocess on the pod.
- `HProfile.identity` is `sha256` of the whole manifest (`core/sentence/profile.py:183`), and the manifest includes `seed` and `source_seed` (`profile.py:108-124`). A grouping key equal to the identity would make every seed its own group, the exact failure `config_hash`'s docstring names (`sinks.py:209-213`). So `config_hash` for H = `sha256(manifest with the sweep seed removed)[:12]`.
- `MetricSink` (`ladder/capture/ports/metric_sink.py:27-40`) exposes `log`, `log_artifact`, `finish`; the module docstring (`:1-7`) marks it `kind: door, frozen_after: p3b`. Run tags are written at `create_run` from the descriptor (`adapters/mlflow.py:467`) and inside `log_artifact` as `dvc/<file>_md5` / `_remote` (`:763-765`). `finish()` always `set_terminated(status="FINISHED")` (`:866`). H checkpoints are sealed to R2 in `object_worker`'s `checkpoint` callback (`:295-330`) with `publish_worker_snapshot`, `l3_seconds` and `publication_timing` (`:262`, `:315`, `:379`); snapshot records carry `sha256` and `size_bytes` (`worker_snapshot.py:101`, `:135`). Nothing reaches the MLflow run.
- `composition/cli.py` runs the local probe through `run_probe_training(profile, source, output, ...)` with no `sink` (`:144-153`), so `just h-train-probe` writes no `metrics.jsonl` and no MLflow run. `composition.cli` is a reader-tuple member (`ladder/run/checkpoint.py:67`); `composition.entrypoints.cli` is not.
- Pins that must stay green: `tests/test_tracking_sinks.py` (descriptor immutability `:45`, metadata threading `:85`, legacy builder exactness `:106`, door admits only H and legacy extractors `:212`), `tests/test_sinks.py` (84 tests), `tests/test_h_worker_command_observability.py` (2), `tests/test_cli_surface.py` (14; names `h-train-probe`), `tests/test_sentence_cli.py`, `tests/test_h_lane_live.py`, `tests/test_h_metric_routing.py:46`.
